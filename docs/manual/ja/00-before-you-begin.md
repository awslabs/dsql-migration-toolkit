# 0. はじめる前に

_言語: [English](../en/00-before-you-begin.md) | [한국어](../ko/00-before-you-begin.md) | **日本語**_

マイグレーションを始める**前に**、この短いページを読んでください。Aurora DSQL は
ソースエンジン（MySQL または PostgreSQL）をそのまま置き換えられるドロップイン代替では**なく**、
独自のルールを持つ分散型エンジンです。そのため、いくつかの事実が最初のステップから計画を左右します。
（PostgreSQL ソースは DSQL により近く、両者とも PostgreSQL-16 のワイヤプロトコルを話しますが、
それでも DSQL の制約をそのまま受けるため、異種（heterogeneous）マイグレーションという心構えは
依然として当てはまります。方言の差が MySQL より小さいだけです。）以下の各項目は、一行の
「必ず知っておくべきこと」と、それを詳しく扱う章へのポインタです。

> このページは**プリフライトチェックリスト**です。詳細な各章を置き換えるものではありません。
> ある方式に*すでにコミットしてしまった後で*制約を発見する事態を防ぎます。強制される
> 全体の制限は [第 6 章 — 制限](06-limitations.md) にあります。

## プリフライトチェックリスト

- [ ] **ソースとターゲットは同一の AWS リージョンにあること。** このツールは Aurora DSQL が
      利用可能などのリージョンでも動作しますが、**ソースとターゲットは同一リージョンになければ
      ならず**、**クロスリージョンのマイグレーションはサポートされません**。オプションの CDC
      パイプラインも単一のリージョン/VPC で実行されます。ツールもそのリージョンで実行してください。
      → [§1.5](01-setup.md#15-ソースとターゲットへの接続),
      [§6.2](06-limitations.md#62-移行プロセスの制限)

- [ ] **ソースはほぼすべての経路で読み取り専用です。** MySQL、および PostgreSQL の Full Load 専用
      マイグレーションでは、ツールがソースに書き込むことは決してなく、読み取り可能なユーザーで十分です。
      唯一の例外は **PostgreSQL CDC** です: Full Load の一貫性ポイントで、ツールは論理レプリケーション
      スロットと、マイグレーション対象テーブルだけに限定したパブリケーションを作成し — teardown 時に
      再び削除します（自動コミット、小さな allowlist に限定、監査記録あり）。これがツールがどのソースに
      対しても行う唯一の書き込みです。 → [§1.1](01-setup.md#11-前提条件)

- [ ] **2 つのソースエンジンをサポートします。** **RDS for MySQL** と **Aurora MySQL**（**5.7 / 8.0 /
      8.4** バージョン）、および **RDS for PostgreSQL** と **Aurora PostgreSQL**（PG **13–16** を検証。
      ツールは PG のバージョン下限/上限を強制しません）。ソースエンジンは Connect 画面で選択します
      （MySQL の既定ポートは **3306**、PostgreSQL は **5432**。PostgreSQL ソースは単一のデータベースに
      接続します）。どちらのエンジンもパスワードまたは **AWS Secrets Manager** のユーザー名/パスワードで
      認証します — IAM 認証はターゲット DSQL 専用です。 → [§1.1](01-setup.md#11-前提条件)

- [ ] **DSQL は PostgreSQL 互換・IAM 認証・分散型です。** PostgreSQL のワイヤプロトコルを話し、
      **短命の IAM トークン**（管理すべきパスワードなし）を使用し、**OCC(楽観的並行性制御)**（ロックなし）
      を用います。ツールには DSQL の**クラスターエンドポイント**と、それに接続できる AWS アイデンティティを
      渡します。 → [§1.1](01-setup.md#11-前提条件),
      [§1.5](01-setup.md#15-ソースとターゲットへの接続)

- [ ] **DSQL に移行するすべてのテーブルには主キーが必須です。** DSQL は**主キーによって**データを
      分散・格納するため PK が必須であり、ツールの Full Load も PK 順にデータを読み取ります。PK の
      ないテーブルはマイグレーションできません — Evaluation がそれを `UNSUPPORTED` としてフラグし、
      Full Load も拒否します。ロード前にそうしたテーブルに PK を追加してください。（単一カラム・
      複合 PK のいずれもサポートされます。）
      → [§6.1](06-limitations.md#61-aurora-dsql-の機能制限スキーマがこれらに適合している必要があります)

- [ ] **DSQL はソースエンジン（MySQL または PostgreSQL）が持ちうる機能の一部を意図的に省いています。**
      **トリガー / ストアドプロシージャ / イベント**なし、**トランザクションあたりの行数制限（≤ 3000）**、
      **値あたり 1 MiB 制限**、`DECIMAL` の**精度 ≤ 38**、そして**空間型なし**。（**外部キーはサポート
      されます** — Aurora DSQL が外部キーを強制します — ので、ツールはこれらを保持し、データロード後に
      再作成します。省略される機能では*ありません*。）これらを自分で見つける必要はありません
      — **Evaluation** ステップがスキーマを検査し、それぞれを推奨アクションとともに
      `AUTO` / `MANUAL` / `UNSUPPORTED` としてフラグします。**PostgreSQL ソース**の場合、Evaluation は
      DSQL が格納できない PG 固有のカラム型 — 配列、幾何（geometric）、ネットワーク
      （`inet`/`cidr`/`macaddr`）、`xml`、`money`、`bit`/`varbit`、`tsvector`/`tsquery`、range/multirange、
      `enum`、複合（composite）、`pgvector` — も `UNSUPPORTED` としてフラグするので、作り直してください。
      データをロードする前に、`UNSUPPORTED` 項目を解決し、`MANUAL` 項目を判断する計画を立ててください。
      → [第 2 章](02-evaluation-and-schema-conversion.md),
      [第 6 章](06-limitations.md)

- [ ] **CDC はオプションであり、実行中は課金されます。** ストリーミング CDC が必要になるのは、
      大規模なカットオーバーや、ほぼゼロダウンタイムのカットオーバーの場合だけです。CDC は MSK +
      MSK Connect（場合によっては NAT ゲートウェイ）をプロビジョニングし、それらを撤去するまで
      費用がかかります。短い凍結（フリーズ）を伴う一回限りのマイグレーションであれば、**Full Load
      単独**で十分であり、ストリーミングインフラをプロビジョニングしません。
      → [第 4 章](04-cdc-and-dsql-constraints.md),
      [§10.1](10-conclusion.md#101-どの経路が必要か)

- [ ] **CDC はまずソース側の設定が必要で — エンジンごとに異なります。** CDC を使う場合、前提条件ゲートは
      ソースが準備できるまで CDC を**ブロック**します。Full Load 単独ではこれらは一切不要です。
      → [§1.1](01-setup.md#11-前提条件)
    - **MySQL ソース:** **バイナリロギングを ROW フォーマット・フルローイメージで有効化**し
      （`binlog_format=ROW`、`binlog_row_image=FULL`）、**レプリケーション権限**を持つユーザーを用意します。
      さらに、Full Load ウォーターマーク時点の binlog が CDC 開始時まで残るように **binlog の保持期間を
      延長**してください（この項目についてゲートは**警告するのみ**ですが、保持期間が短すぎると実際に
      silent-gap のリスクがあります）。RDS/Aurora では、これは**パラメータグループ**と
      `mysql.rds_set_configuration` **ストアドプロシージャ**で設定します — コミュニティ版 MySQL のような
      `my.cnf`/`SET GLOBAL` ではありません。
    - **PostgreSQL ソース:** **`wal_level=logical`** を設定します（RDS/Aurora では、カスタム DB/クラスター
      パラメータグループに静的パラメータ **`rds.logical_replication=1`** を設定してから**再起動**します —
      Aurora では writer を再起動。自己管理型では `wal_level=logical` を設定して再起動）。**レプリケーション
      権限**を持つユーザー（superuser、**REPLICATION** ロール属性、または RDS/Aurora の
      **`rds_replication`** メンバーシップ）が必要で、ソースは standby ではなくクラスターの **writer**
      エンドポイントである必要があります（`pg_is_in_recovery()` = false）。さらに、**複製対象のすべての
      テーブルに使用可能な `REPLICA IDENTITY` が必要です** — 主キーがあれば既定で満たされ、なければ
      `ALTER TABLE … REPLICA IDENTITY FULL` を設定してください（`REPLICA IDENTITY NOTHING` は拒否
      されます）。レプリケーションスロット / walsender の**余裕**は、ブロックしない**警告**として
      チェックされます。**パブリケーション**と**論理レプリケーションスロット**はツールが自動で作成します。

- [ ] **CDC が複製するのはスキーマではなくデータです。** CDC 中、ソースの **DDL** 変更は DSQL に
      **伝播されません** — Schema Conversion によって自分で再適用します。
      → [§4.2](04-cdc-and-dsql-constraints.md#42-cdc-は-スキーマ-ではなく-データ-を複製する--重要)

- [ ] **認証情報はセッションメモリ内にのみ存在します。** ディスク、ログ、レポートに書き込まれることは
      決してなく、セッション終了時に破棄されます — そのため再起動後は接続情報を再入力します。
      → [§1.5](01-setup.md#15-ソースとターゲットへの接続)

- [ ] **AI アシストはオプションで、Amazon Bedrock 専用です。** AI は**デフォルトでオフ**です。有効に
      すると、AWS 認証情報（`bedrock:InvokeModel` 権限）を使って**もっぱら Amazon Bedrock を通じてのみ**
      動作します。**直接 API キーを入力する手段はありません**（Anthropic/OpenAI のキー入力欄はありません）
      — AI を使う唯一の方法は Bedrock です。すべての提案は**レビュー専用**であり、AI がデータ経路に
      入ることは決してありません。同じアシスタントが **すべてのステップ** で **AI DBA** パネルとして
      利用できます — Full Load / CDC の失敗診断、DLQ のトリアージ、前提条件チェックを行う読み取り専用の
      ヘルパーです。 → [第 2 章](02-evaluation-and-schema-conversion.md), [第 9 章](09-query-validation.md)

- [ ] **（AWS にデプロイする場合）オプションの認証を備えた単一タスクのコントロールプレーンです。**
      通常の形態は ALB の背後にある **ECS Fargate** タスク 1 つで、ALB の**オプションの Cognito** ゲートを
      使います（インターネットに面するデプロイでは必ず有効にしてください）。AWS ホスト形態のデプロイでは、
      ジョブ/セッション状態はマネージド S3 バケットに durable に保持され、タスク入れ替え後も再開できます。
      **単一 EC2 ホスト（ソースから）** モードもあります — 状態は保持される EBS ボリューム、接続は SSM
      ポートフォワード、ALB/Cognito なし。 → [§1.4](01-setup.md#14-単一-ec2-ホストで実行する-ソースから),
      [§6.3](06-limitations.md#63-デプロイの制限aws-ホスト形態)

## 心構え

これをアップグレードではなく**異種（heterogeneous）マイグレーション**として扱ってください。この
ツールの役割は、DSQL の差異を最初に明示し（**Evaluation**）、決定論的に変換できるものを変換し
（**Schema Conversion**、**Full Load**、**CDC**）、その結果を証明すること（**Validation**）に尽きます。
上記のチェックリストを体得すれば、マニュアルの残りはその詳細にすぎません。
