# 6. 한계

_언어: [English](../en/06-limitations.md) | **한국어**_

계획에 반드시 반영해야 하는 **실제로 강제되는** 한계입니다. 대부분 Aurora DSQL 자체에서 옵니다(분산형이며
수평 확장에 맞지 않는 기능을 의도적으로 제외), 일부는 배포 방식에서 옵니다. 어느 것도 런타임의 깜짝
놀라움이 아닙니다: 도구가 **Evaluation**에서 플래그하고, 가능한 곳에서 처리하며, 불가능한 곳에서는
**시끄럽게** 실패합니다.

---

## 6.1 Aurora DSQL 기능 한계 (스키마가 이에 맞아야 함)

| 한계 | 결과 | 도구 동작 |
|---|---|---|
| **외래 키 없음** | DSQL에서 참조 무결성은 애플리케이션 책임. | FK 정의는 DDL에서 제거하되 리포트에 보존; **MANUAL** 플래그. |
| **기본 키 필수** | PK 없는 테이블은 마이그레이션 불가. | **UNSUPPORTED** 플래그; Full Load도 차단(keyset export에 PK 필요). |
| **트리거/저장 프로시저/함수/스케줄 이벤트 없음** | 서버 측 로직은 옮겨지지 않음. | **UNSUPPORTED** — 애플리케이션으로 재구현(이벤트 → EventBridge/Lambda). |
| **네이티브 파티셔닝 없음** | DSQL이 직접 자동 분산. | 파티션 테이블 **MANUAL**(파티셔닝 제거). |
| **값당 1 MiB 한도** | ~1 MiB 초과 단일 `TEXT`/`BLOB` 값 저장 불가. | 1–8 MiB 값은 에러 로그/DLQ로 **quarantine**; > 8 MiB 컬럼은 **캡처에서 제외**해야 함. 대형 LOB 컬럼은 `OVERSIZED_LOB`(MANUAL). |
| **`DECIMAL` 정밀도 > 38** | 더 높은 정밀도 미지원. | **UNSUPPORTED**(`NUMERIC_PRECISION`). |
| **공간/geometry 타입** | 미지원. | **UNSUPPORTED**. |
| **FULLTEXT / SPATIAL 인덱스** | 미지원. | **UNSUPPORTED**. |
| **테이블당 ≤ 255 컬럼, DB당 ≤ 1000 테이블** | 초과 시 미지원. | **UNSUPPORTED**(`TOO_MANY_COLUMNS` / `TABLE_COUNT_LIMIT`). |
| **클러스터당 하나의 DB** | DSQL은 다중 DB가 아니라 스키마로 구성. | 다중 DB 소스 **MANUAL**(스키마로 통합 또는 클러스터 분리). |
| **`TRUNCATE` 없음; 트랜잭션당 한 개 DDL; 낙관적 동시성** | MySQL과 다른 쓰기/DDL 의미. | 투명 처리: TRUNCATE 대신 DROP+재생성, 단일 DDL 단위, 곳곳에 `40001` 재시도. |
| **IAM 토큰 인증(비밀번호 없음); 단기 토큰** | 정적 DB 비밀번호 없음. | 도구(와 CDC 싱크)가 IAM 토큰을 자동 발급·갱신. |

> **스키마 설계의 결론:** 관계 무결성, 대형 blob, 서버 측 로직, 매우 높은 정밀도 숫자는 DSQL에
> 의존하기 *전에* 데이터베이스 밖 애플리케이션으로 밀어내세요. Evaluation이 어떤 객체가 이를 필요로
> 하는지 정확히 알려 줍니다.

## 6.2 마이그레이션 프로세스 한계

- **단일 리전 — 크로스 리전 마이그레이션 없음.** 도구는 DSQL을 지원하는 어느 리전에서나 동작하지만,
  **소스와 타깃은 동일 리전에 있어야 하며** 선택적 CDC 파이프라인은 단일 리전/VPC에서 실행됩니다. 크로스
  리전은 지원되지 않습니다.
- **CDC는 소스 측 사전 요건(binlog)이 있음.** CDC는 소스에 바이너리 로깅이 **ROW 포맷·full row
  image**로 켜져 있고(`binlog_format=ROW`, `binlog_row_image=FULL`) **복제 권한**을 가진 사용자가
  있어야 합니다 — 사전 점검 게이트가 이를 충족할 때까지 **CDC를 차단**합니다. 또한 Full Load 워터마크
  위치의 로그가 CDC 시작까지 남도록 **binlog 보존을 늘려야** 합니다(Aurora MySQL은 기본 24시간만 보존).
  RDS/Aurora에서는 `my.cnf`가 아니라 파라미터 그룹과 `mysql.rds_set_configuration`으로 설정합니다 —
  [§1.1](01-setup.md#11-사전-요구사항) 참조. (Full Load만 한다면 이 중 아무것도 필요 없습니다.)
- **CDC는 데이터를 복제하지 DDL은 아님.** CDC 중 소스 스키마 변경은 DSQL로 **전파되지 않으므로** 동일
  DDL을 DSQL에 직접 적용해야 합니다
  ([4장 §4.2](04-cdc-and-dsql-constraints.md#42-cdc는-스키마가-아니라-데이터를-복제--중요) 참조).
- **CDC는 배포 중 과금됨.** 스트리밍 파이프라인(MSK Serverless + MSK Connect, NAT 게이트웨이를 만들면
  포함)은 실행되는 동안 비용이 듭니다. 전환 후 cdc-stack을 내리세요. Full Load만으로는 스트리밍 인프라가
  프로비저닝되지 않습니다.
- **TINYINT(1) 범위 초과는 설계상 테이블 전체 실패.** `{0,1}` 밖의 `TINYINT(1)` 값은 그 테이블의 Full
  Load를 조용히 `true`로 평탄화하지 않고 시끄럽게 멈춥니다. 소스 데이터를 정리(또는 컬럼 제외)하고 다시
  실행하세요.

## 6.3 배포 한계 (AWS 호스팅 형태)

- **단일 태스크 컨트롤 플레인.** 도구는 **하나의** ECS Fargate 태스크로 배포됩니다. 작업/세션 상태는
  태스크의 **임시 스토리지**에 로컬 SQLite로 있으므로, 태스크 교체(배포, 크래시)는 진행 중 작업 상태를
  잃습니다 — 재연결해 읽기 전용 단계를 다시 실행합니다. 그 상태를 공유 저장소로 옮기지 않고 두 개 이상의
  태스크로 확장하지 마세요. 무손실 재개가 필요하면 작업/세션 상태 경로를 공유 EFS 마운트로 지정할 수
  있습니다([`deploy/DEPLOYMENT.md`](../../../deploy/DEPLOYMENT.md) 참조).
- **앱 자체 인증 없음.** 앱은 ALB의 **선택적 Cognito** 게이트에 의존합니다. 인터넷 노출 배포에서는
  Cognito를 켜세요 — 배포 템플릿이 Cognito 없는 인터넷 노출 조합을 막습니다.
- **자격증명은 세션별·메모리 전용.** 절대 영속되지 않으며, 재시작은 소스/타깃 연결 정보 재입력을
  의미합니다.
